# Agent 与 API 供应商审查

审查日期：2026-10-27（本机时间）。范围：当前实际运行的 Atelier、Agent、供应商设置、普通对话选择器，以及对应的 Python 请求与任务链路。本轮只审查，未修改业务代码或供应商配置，未调用付费 API。下面的复现断言描述现存问题，不代表修复验收通过。

## 结论

尚未完整统一。共享供应商存储、加密密钥、基础表面色彩、输入法保护和阅读位置逻辑已经存在；Agent 仍保留旧的请求分支和交互结构。普通对话、Agent 与供应商设置没有共享完整的模型能力、运行状态和连接诊断模型。上一轮通过的自动测试没有覆盖本次发现的分支。

Claude 方向在这里指清晰的内容层级、就近模型选择、轻量但完整的运行反馈与可靠交互。它不意味着所有服务都改用 Anthropic 协议，也不意味着把社区参考组件原样移植。参考依据仍是 `DESIGN.md` 和 `docs/open-claude-ui-reference.md` 固定提交；未将 Claude 登录后的当前界面声称为本轮已访问。

## 确认的问题与优先级

P1 表示优先修复：可能错用供应商、混用凭据或使运行任务失去可靠控制。P2 表示影响兼容性、诊断准确性或常用操作。

### A01 · P1：失效供应商会静默换成另一供应商

`backend/moss_server/bridge.py:63` 在指定 ID 找不到时，自动选择第一个启用的供应商；已存在但停用的供应商没有在这里拒绝。删除当前供应商不会同步修复工坊中的 `provider_id`。因此“当前配置无效”可能演变成文稿送往用户未选择的服务，OpenAI Chat 的旧分支仍可通过此桥接调用。

隔离复现：请求 `deleted-provider` 实际解析为 `fixture`；`enabled=False` 的 fixture 仍能被解析。建议：指定 ID 失效/停用立即报错；只有首次无选择状态才允许明确的默认项；删除被引用的供应商应先解决引用关系。

### A02 · P1：新增供应商沿用上一项未保存的 Key

`frontend-src/src/components/SettingsDrawer.tsx:67` 的 `create()` 没有清空独立的 `apiKey` 状态。复现步骤是给旧项输入测试 Key，点击新增；新项的密码框仍持有该 Key，随后保存会写入新供应商的密钥槽。这不是已观察到的真实凭据泄露，但确实会混用凭据。

组件隔离测试已复现。建议将编辑草稿与密钥意图绑定供应商 ID；新增、切换和成功提交时显式重置。增加独立的“清除加密保存的密钥”操作，环境变量覆盖时说明实际生效来源。

### A03 · P1：后台任务可继续，Agent 前端却无法重连

`frontend-src/src/features/studio/api.ts:145` 只发起一次 fetch。取得的任务 ID 仅用于取消，没有保存事件序号、读取 SSE `id`、重连或刷新后重新附着。`store.ts:189` 将运行状态视为易失状态，读取结束后在 `store.ts:1119` 清空它。后端已有 `/api/v1/jobs/{id}/events?after=`，但没有接到 Agent 客户端。

后端 `moss_server/api.py:262` 每次请求都会新建任务，也没有同一会话的活动任务约束。因此断线后前端可能看似空闲，后台仍在运行，再发送可出现两个生产者操作同一会话。此项由端到端代码链路确认，未在用户正式会话中制造断线或双任务。

建议持久化 run ID / session ID / 最后事件序号；刷新先恢复活动任务；断线显示“正在重连”，取消保持针对原任务；后端为会话执行加锁或显式排队。恢复事件不能重新执行工具。

### A04 · P1：一次 Agent 运行没有固定自己的供应商与模型配置

任务记录只包含 `session_id`、`page_id`；Agent 虽在开始时读取设置，`llm.stream_chat()` 每个工具回合仍重新读取全局设置与供应商。运行中修改主模型/供应商，可能让后续回合改走新服务。`bridge.model_chain():77` 又把供应商列出的全部模型自动放入后备链，即使用户的“后备模型”为空；模型列表可能含视觉、非对话模型或不期望使用的档位。

隔离复现：只配置主模型 `text-main`，无显式后备项，链中仍出现 `vision-only`。建议提交时保存连接、模型、协议、参数、工具集合与后备链快照；只重试用户明确指定且能力适合的模型，并展示实际切换原因。

### A05 · P2：Agent 的 OpenAI Chat/本地引擎仍有旧请求旁路

`backend/moss_server/llm.py:90` 自己拼装 OpenAI Chat 请求，而普通对话与共享请求层使用引擎适配器。它不会完整保留本地档案的采样/思考请求差异，模型链从文件名推测模型 ID，未以实际引擎暴露的 ID 为准。

隔离请求捕获显示本地 Agent 会发送猜测的 `weights.ninfer`。这不能证明每个真实 NInfer 档案一定失败，但存在已知的未知 ID 拒绝风险。本轮没有启动真实 NInfer。建议把 Agent 也收敛到统一传输，实际查询/解析模型标识，保留三引擎能力差异。

### A06 · P2：原生协议丢参数，工具降级也未统一

`backend/atelier/providers.py:68` 只给 OpenAI Chat 补温度、top_p 与输出预算；Anthropic 温度未传，Responses 输出预算未转换。`llm.py:87` 的 `temperature or .7` 又把合法的 0 变成 .7。参数是否允许组合应依模型能力判断，不能全部机械发送。

原生协议在拒绝 tools 时抛 `ValueError`；Agent 的自动标签协议降级只捕获 `ToolsUnsupported`。两种原生协议还绕过旧的后备模型循环。隔离复现已确认参数缺失，以及 HTTP 400 tools 拒绝返回 `ValueError`。建议用统一错误分类、参数映射与有边界的重试策略，全部协议执行同一状态机。

### A07 · P2：连接探测可能假成功，模型列表被误报为能力失败

`providers.stream():123` 即使 HTTP 200 的事件流完全为空，也无条件产出 done；`moss_server/api.py:698` 随之认定 chat_ok / ok 为 true。隔离复现得到 `ok=true, chat_ok=true, stream_ok=false, tools_ok=false, message=连接正常`。

前端 `SettingsDrawer.tsx:121` 又把“只拉取模型列表”的结果显示成“可用（流式✗ / 函数调用✗）”，实际根本没测这两个能力；组件测试已复现。工坊模型列表接口还使用独立的 Bearer 认证路径，没有复用供应商页的协议头适配。建议区分未知、未测试、通过、失败；验证完整终止事件和有效内容/工具调用；模型发现与推理探测独立展示，并复用相同协议适配。

### A08 · P2：供应商编辑缺少草稿与提交闭环

`SettingsDrawer.tsx:66–71` 切换条目直接替换草稿，关闭后重新打开也会重载；没有未保存保护。改变“类型”会将自定义名称、Base URL、默认模型一起换成官方预设；组件测试确认自定义网关被改写。保存配置与保存 Key 是两个请求，中途失败可能只保存一半。保存/拉取按钮无统一 busy 禁用，旧响应也可能覆盖后来选择的草稿。

供应商变化只通知普通对话的刷新计数；Agent 只监听工坊设置事件，供应商页保存/删除后可能保留旧的公开设置。建议使用带 ID 与 revision 的编辑会话、未保存提示、明确的预设应用动作、提交状态和全局 Query 失效；分别准确报告配置/密钥保存结果，或提供原子提交接口。

### A09 · P2：Agent 与供应商没有统一的前端状态组件

供应商抽屉没有直接连接测试，状态混淆“已保存密钥”和“服务可用”；Agent 输入区的模型只有静态小字，主模型为空时该入口空白；实际运行模型又在消息尾部单独出现。没有统一呈现准备、思考、调用工具、等待回答、等待改动确认、重连、失败和结束。

这是截图步骤 1、2、3、5 及组件源码共同确认的界面缺口。建议共享模型选择器、能力状态条、任务状态条和错误恢复入口。保留 Atelier 自身品牌、文稿提案与工具语义，避免只是照搬一排 Claude 外观控件。

### A10 · P2：可访问性与工具详情仍有缺口

Agent 会话标签使用带点击事件的 div，没有键盘选择语义；思考折叠按钮没有 aria-expanded/aria-controls；工具步骤为 span，结果放在 title，不能可靠地用键盘/触屏查阅。Agent 输入区缺明确的程序化标签。窄屏图标较小，需逐项核对实际命中区域。

建议给会话完整的按钮/标签页键盘行为，折叠控件表达展开状态，工具调用使用可展开的参数/结果详情，输入区明确命名。截图与静态代码审查不能替代屏幕阅读器或完整 WCAG 验收。

## 建议补齐的功能

| 功能 | 应有行为 | 优先级 |
|---|---|---|
| 统一模型选择器 | 搜索、按供应商分组、显示实际默认模型与视觉/工具/推理能力；对话/创作/视觉保持各自偏好 | 高 |
| 供应商诊断 | 配置有效性、密钥来源、模型发现、流式/工具/视觉能力分别报告；记录测试对象与时间，改配置后失效 | 高 |
| Agent 运行中心 | 当前任务、阶段、耗时、排队、停止、重连、等待用户/提案；刷新附着原任务 | 高 |
| 可检查的工具调用 | 来源、名称、结构化参数、执行中、结果与错误详情；MCP 和内置工具用同一种呈现 | 高 |
| 参数与后备策略 | 能力驱动的参数、显式后备链、首 token 前有界重试、切换记录；不重放已执行工具 | 高 |
| 上下文信息 | 当前页/选区/素材/Skills/附件摘要；模型已知时显示预算，未知时不伪造数字 | 中 |
| 配置编辑体验 | 预设与协议分开、未保存保护、手动模型条目、清除保存密钥、连接高级项按需展开 | 中 |

建议实施顺序：先修 A01–A04 的供应商/凭据/任务归属，再统一 A05–A08 的传输与诊断，最后完成 A09–A10 的组件、状态和窄屏精修。UI 重构时分别保留普通聊天与创作文稿的交互语义。
