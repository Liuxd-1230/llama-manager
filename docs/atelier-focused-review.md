# Atelier 重点界面评审 · 2026-10-27

本轮范围：成稿、Anima 预设、工作流保存、素材记事本、Preset（按用户所写 present 理解）、Agent 与普通对话的圆角、Claude 参考布局和动效。结论是**尚未通过整体评审**：保存主流程存在可用部分，但工作流切换、预设参数继承和聊天组件统一仍有明确缺口。本轮未修改业务实现。

## 优先修复项

### F01 · P1：Anima 模板参数被通用出图参数覆盖

模板 KSampler 的参数为 `steps=28, cfg=4.5, scheduler=sgm_uniform`。新工作区自身初始化为 `20, 7, normal`，导入后没有按工作流解析这些初始值，又会通过 700ms 自动保存写到全局 `comfy_params`，生成提交时使用面板值。这意味着“使用 Anima 预设”并不保证使用预设的采样参数。

本轮保存后的后端读回确认：节点仍为 28/4.5/sgm_uniform，而 `comfy_params` 为 20/7/normal；没有提交真实生成。代码位置：`ComfyWorkspace.tsx:53`、`:75`、`:235`。建议明确区分“沿用工作流”和“本次覆盖”，导入时展示差异，参数按工作流保存。

### F02 · P1：切换工作流后前端仍持有旧绑定

实际建立两个工作流：A 的节点为 1–9，B 为 101–109。在界面切到 B 后，后端正向绑定是 `104.text`，界面却仍显示 `#4.text`，其他绑定也残留 A 的编号。截图 08 与 `evidence/workflow-switch-evidence.json` 对应。

原因：`applyStatus()` 仅在 `restore=true` 时 `setBindings`，`switchWorkflow()` 却调用 `loadStatus(false)`。图已更新但绑定未更新。继续修改绑定可能把旧映射保存到新工作流。建议切换时原子载入工作流、绑定、布局与参数；保存请求带工作流 ID，处理未完成的防抖保存。代码位置：`ComfyWorkspace.tsx:75`、`:143`、`:196`。

### F03 · P2：Anima 按钮暴露原始 JSON，缺少可理解的配置步骤

点击预设后会出现 JSON 文本、名称输入和空节点视图，用户仍需理解“填入”与“保存为新工作流”的区别。模型文件名写死，离线导入只说明结构可保存，不能说明所需文件、节点和模型兼容性已核对。本轮没有把 ComfyUI 连接或 Anima 真实出图算作通过。

建议提供预设摘要、模型文件选择/缺失状态、参数和正负提示词预览，再确认保存。保留 API JSON 作为高级入口。对照外部来源时使用 [Comfy 官方 Anima 模板入口](https://comfy.org/workflows/ab2f354cd396-ab2f354cd396/)；本轮未完成该官方模板 JSON 的下载和逐节点验证，因此不声称现有模板完整等价。

### F04 · P2：成稿的空间与编辑节奏需要精修

`creative.module.css` 给每段 textarea 设置 140px 最小高度，短文字也占据很大空白；1920px 时文稿行宽继续扩展，而 Agent 仍较窄。390px 时项目/系列/分页/模式与编译工具占去不少高度。固定片段的可读性应保留，不能把“不可改”做成接近禁用文本。

建议按内容自适应高度、给正文设舒适行宽、长段落按需展开；小屏优先保留正文与输入，把辅助工具收进就近菜单。已有固定、译文、差异与版本保护应保留。截图 01–05。

### F05 · P2：记事本和 Preset 可以保存，但缺少专门的编辑体验

两者仍套用通用素材表单。笔记长文在约 340px 的详情栏编辑，大面积列表区空置；窄屏编辑器排在列表之后，保存和引用需要向下寻找。Preset 的系统提示默认 12 行，短内容也占去大量高度；列表不预览规则和参数，只有“点击编辑与复用”。当前页面也没有未保存保护和明确编辑状态。

记事本已实际增加“评审保存检查”行，保存后重载仍在；Preset 由 0.65 改为 0.55，保存并重载确认保留。建议分别做笔记正文编辑器和紧凑的 Preset 编辑器，显示保存状态、当前引用与使用范围。截图 09–12。

### F06 · P2：素材引用没有清楚表达作用范围与覆盖关系

记事本/Preset 已能引用当前页，Agent 将它们作为用户选择的参考。多个 Preset 会按遍历顺序覆盖 temperature/top_p，界面没有说明谁最终生效。Top P 输入上限还与 Temperature 一样允许到 2，未按模型能力约束。引用条直接显示 `preset/notebook/character` 内部类型名。

`creation.py` 的普通文本/MOSS 编译只主动加入标签、画师和 LoRA，Anima 主要读取角色书、画师、标签及 LoRA；段落润色请求也未直接携带这些引用。因此不能将笔记/Preset 的引用提示理解为对所有编译、翻译和润色自动生效。建议标注“作用于 Agent / 编译 / 润色”等范围，明确单个活动 Preset或覆盖顺序，并显示最终参数。截图 13。代码位置：`AssetsPage.tsx:14`、`:31`，`agent.py:253`，`creation.py:22`。

### F07 · P2：圆角与输入区尚未统一到同一体系

浏览器实际样式读数：普通对话用户气泡为 `6px 6px 2px`（第四角同 6px），Agent 用户气泡为 `12px 12px 4px`（第四角同 12px）；普通对话 textarea 为 4px，Agent 输入容器为 12px。普通对话正文为 14px，Agent 输入/气泡为 13px。模型选择、工具记录与思考又采用不同结构。

圆角统一应是按角色统一：共享 Composer、用户气泡、模型菜单、工具详情和折叠控件，不是全站都改成同一个数值。可采用 6px 小控件、12px Composer、16–18px 气泡作为评审起点，再按实际视觉确定；保留 Λ 与 Atelier 字体品牌。数值建议不是 Claude 官方规范。截图 04–05、14–18；实际读数见 evidence 内两个 computed-style JSON。

### F08 · P2：Agent 与对话未完成 Claude 参考的结构与动效适配

社区参考把输入、附件、模型、思考与发送聚合为一个输入终端，正文和工具展开有明确层级。当前普通对话仍是顶部长工具栏＋独立 textarea/发送按钮；390px 工具栏多行堆叠，留给消息的高度很少。Agent 仍使用另一套 `.btn/.bubble/.step/.reasoning`；工具结果主要依赖 title，思考字数小，缺少统一的运行阶段、耗时和重连反馈。

已有消息 180ms 入场、分段选中背景 160ms、品牌与提案动效，但思考/工具展开仍主要是条件渲染或原生 details，没有共同的高度过渡与状态收口。历史重载与新到消息也没有完整区分。建议共享 ChatSurface、Composer、ReasoningDisclosure、ToolCallDetails 和运行状态条，以动作触发反馈；保持手动阅读和减少动态效果支持。

本轮实际点击展开/关闭并审查 CSS/组件；静态截图无法证明逐帧效果。未录制动画视频，未将动效实现检查描述为完整性能或屏幕阅读器验收。详见 `MOTION.md`。
