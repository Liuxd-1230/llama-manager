# Atelier 真实使用修复与精修 · 2026-10-27

本轮在当前项目中定向修改，保留既有设计、工作流参数保护及数据。正式服务为 9090；有写入的模型、下载和浏览器验收使用 9092、独立 ATELIER_DATA_DIR。未提交 ComfyUI 生图，也未启停外部 ComfyUI。以下将真实执行与受控回归分开记录。

## Agent：真正的增量输出

**复现条件**：同一份中文长回答提示，分别请求普通对话 `/api/v1/chat` 和创作 `/moss/sessions/{id}/run`，记录原始 SSE 及最终保存消息。

普通对话经过提供商适配、SSE 消费和 reducer 更新，原测试得到 1064 个正文增量、1467 字、首增量 0.531 秒。Agent 多了一条工具与标签处理 → 持久化事件 → 订阅 → Zustand 的链路；原测试仅交付 213 个增量、303 字，数据库却保存了 1737 字，而且订阅缺少 done。

**根因与修改**：

- 逐 token 同步 SQLite 连接与提交阻塞事件循环；事件写入和查询改为线程执行，仍先持久化真实增量再交付。
- 订阅发送一批数据时，生产者可能已结束。原先随后检查 active 就退出，漏读最后一批；现在必须在生产者结束后读到空批次，才确认尾部已排空。
- 前端曾用“任务已成功”代替“该订阅收到完整结尾”，重新加载消息掩盖丢尾。现在从最后事件 ID 重连原任务，避免重跑工具；取消、异常及重启中断也有终态事件。
- 先停止、后收到响应头的边界改为按请求 ID 取消；取消标识持久化后，迟到的相同 POST 不会执行模型或工具。
- Agent 本地请求沿用推理档案的思考开关；未重新实现既有三种提供商协议。

**真实结果**：修复后原始链路实测 1357 个正文增量、2053 字、首增量 0.609 秒，收到 done。浏览器长回答热态一轮首字 0.917 秒、199 次 DOM 更新、1604 个可见字符；最后录像一轮首字 4.023 秒、136 次更新、1677 个可见字符。两轮运行条件不同，首字时间不是固定性能承诺。180ms 的 Markdown 排版节流只合并已到达的增量，没有逐字播放完成文本。

用户提供的 Gemma-4 E4B Q4_K_M GGUF 和 E:/llama.cpp 的实际服务 DLL 执行了上述推理。另有真实工具 ask_user、停止、连接拒绝、恢复连接后重试和 2033 字思考增量。对应状态分别为 succeeded、cancelled、failed、succeeded、succeeded。真实长回答录像为 `Agent-real-stream.webm`，原始与最终事件、时序、文字保存在评审包。

## 下载：接收、停止与恢复

**复现与根因**：安装环境为 huggingface_hub 1.33。原先默认 10MB 的进度通知和至少两次采样的速度算法，让前一段下载长时间显示 0；原测试的 128KB 补丁掩盖了这个差异。暂停先改 UI 状态、请求仍在运行；排队和等待重试的取消未总是触发传输停止。Hub 1.33 的下载临时文件带进程随机名，旧测试只检查最终文件相等，完整重下也会通过，并未证明 HTTP Range 续传。另一个实际干扰是日志脱敏破坏 Uvicorn 结构化参数，造成每次请求都抛格式异常。

**修改**：

- 保留仓库解析与元数据能力，由 Atelier 管理单文件 HTTP 接收、稳定的版本断点、Range/If-Range、Content-Range 校验、大小与 SHA-256/Git blob 校验、原子完成及 HF 缓存登记。
- 每个正在传输的文件拥有独立受控进程；暂停和取消真正结束请求、等待子进程退出，之后才发布终态。排队、重试、连接、接收和校验阶段均由同一停止信号控制。Windows Job Object 在父进程消失时回收所属下载进程。
- 256KB 接收块，按真实字节和时间采样，进度消息最多约每 100ms 一次；网页刷新合并，显示已下载/总量、真实速度、ETA、连接/接收/校验/暂停等状态。
- 全局取消也调用下载引擎；不能只修改任务数据库。
- 新任务保存文件版本清单。重启恢复先核对清单，沿用原任务 ID。文件变化会停止，保留旧断点并提示重新确认。缺少版本清单的旧任务要求重新解析、新建下载；已有断点不会被删除。相同版本新任务仍可复用兼容断点。
- 源忽略 Range 时明确从头接收，不把它记为无损续传。Token、认证错误、断流重试和磁盘检查保留；没有增加单文件连接数。

## 文件与目录选择

**根因**：网页备用选择器中嵌套容器和列表高度没有形成独立的路径/列表/按钮行，实际截图中产生覆盖。它原本已使用 body portal，不能把所有问题归为缺少 portal。文件夹模式还显示文件，导航后可能保留失效选择，路径不存在会被当成空目录。

**修改**：四行 minmax 布局、独立滚动、移动端触控尺寸；导航清除失效选择、过期响应防护、确认有效目录、文件初始路径解析为父目录。取消保持配置草稿。系统选择请求有独立 ID、迟到取消保护和后台 inert；焦点陷阱跳过 inert 控件。

原生 WinForms 窗口原先使用不可见的微小宿主和独立置顶定位；现在关联前台宿主的根窗口，失去宿主时使用有边界的屏幕位置，取消与超时会回收辅助进程并恢复其原先启用的宿主。

**实际验证边界**：网页备用方案在 1440×900、390×844、1152×720 + 1.25 像素比例（等效 125% 缩放的布局压力）通过无重叠、E:/LmModels 回填及取消不改值。共享选择器覆盖模型配置、下载目录与 LoRA 扫描入口；键盘和嵌套弹层另有回归。原生窗口实际打开与取消有截图；本轮自动化工具无法可靠操作被其他进程拥有的目录树，**原生窗口选择具体目录后回填、多屏与真实浏览器缩放组合仍未完成验收**。等效尺寸测试不冒充实际浏览器缩放操作。

## 对话、历史与品牌

- 普通对话与 Agent 共用 Markdown、表格、嵌套列表、代码复制/换行/预览以及思考、工具折叠与输入表面。保留 Agent 原有中文 prose fence 的可读处理、提案和工具执行。
- 正文维持约 800px 阅读宽度，统一标题/段落/列表节奏。输入框移除嵌套白底、随内容增高；移动端头部收为两行，低频选项继续收纳。
- 三轮真实长对话验证了段落、表格、代码与后续追问。真实 DOM 排版完成后跟随输出；用户向上滚动时不抢位置。测得向上后的 scrollTop=3964，继续生成后仍为3964，回到最新后底部距离=0。
- 读取历史恢复原会话可用的模型服务/模型，并防止迟到的历史请求覆盖较新的选择。
- 浏览器回归稳定复现了新建项目后创作页重复 boot：迟到的工作区响应可覆盖第一笔编辑。进入已加载的项目不再重复 boot；窄屏点击创作视图回到编辑区。延迟真实接口的红/绿回归保留。
- 撤销/重做是当前编辑会话；“文档版本”保存操作前页面状态，可预览并恢复；“Agent 对话”保存本系列会话；出图视图的任务/结果由 generation job 和快照提供；工作流库保存模板、绑定与每工作流参数，导入任务属于解析记录。本轮没有制造一套“工作流执行历史”，也没有删除旧历史。既有恢复保护保留。
- 首页改为较小的简洁品牌板，作品、项目和任务提前进入视线；标志路径、艺术背景和品牌色不变。完整构造仍可主动重播，关于页保留完整场景。功能页只清理重复文案与展示装饰，不更换主题。
